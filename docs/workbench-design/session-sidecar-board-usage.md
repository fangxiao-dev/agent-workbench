# Session 看板：本地运行

可在任意工作目录运行：

```powershell
python D:\CodeSpace\agent-workbench\scripts\session_board.py --db "D:\vibe-code-life\SessionBoard\board.sqlite3"
```

打开程序输出的 `http://127.0.0.1:43188`。进程默认每 30 秒同步，页面关闭后仍继续；按 Ctrl+C 停止服务。顶栏的同步时间可以点开选刷新间隔（30 秒 / 1 分钟 / 5 分钟），页面和后台循环共用同一个值，记在看板库里。默认仅发现最近七天有活动的本机 Claude session；已有 item 的用户设置不会因为超出扫描窗口被移除。首次发现的 session 仅读取记录末尾一段，界面会显示覆盖限制。

服务仅监听本机。必须通过 `--db` 明确指定看板数据库位置：它会包含摘取的 session 文本、看板状态与备注，因此请自行选择访问权限、同步和备份范围合适的目录。每个 session 最多缓存最近 40 条文本、每条最多 2,000 字符；超出七天扫描窗口的条目会保留用户设置，但其缓存文本及摘要会在下次同步时清除。原生 session 为只读来源；“移除”仅隐藏看板 item，并不删除原生 session 或立即清除缓存。

运行中的本机元数据可提供部分状态与 Desktop 链接；信息缺失时显示未知或链接不可用。点击链接会记录从看板发起打开时的已读基准，不代表系统已确认 Desktop 成功打开，也不代表在 Desktop 里读完。

界面是四列看板（进行中 / 最近 / 已完成 / 暂不关注）：新发现的会话进入“最近”，拖到其他列即改变你的状态；卡片只显示标题、状态图标、一句预览（有摘要时为摘要）、项目、标签和时间；每张卡片最多挂 3 个标签，标签和小小的 + 都在页脚，点标签或 + 打开同一个菜单就能挂上或摘掉。点开卡片从右侧抽屉查看最近消息、设置标签与备注、移除。抽屉顶部只保留标题、路径、打开按钮、状态分段和标签；备注默认收起，点“备注”展开。消息按 Markdown 渲染，过长的收起并可展开。新发现的会话视为已读，只有之后的新消息才标“新”。每一栏内的会话按所在目录聚合成可折叠的组（worktree 归到其主仓库目录），折叠状态保存在浏览器本地，“搁置”栏默认折叠；折叠的组头仍会显示运行中和新消息的标记。后台 / 子会话默认不显示：启动入口为 SDK 的程序化会话，或没有标题且首条消息不是人输入的会话；右上角机器人图标可临时显示，角标是被过滤的数量。没有标题的其他会话也不显示。该判断来自本机 transcript 的启动入口和首条消息来源字段，属经验规则，不是官方接口。

摘要默认未启用，不会自动向模型服务发送 session 内容。通过 `--summary-command` 传入 JSON 字符串数组可显式启用受信任的摘要命令；命令从标准输入接收 JSON（标题、备注、最近最多 8 条消息），从标准输出返回包含 `summary` 和 `attention` 字符串的 JSON。该命令可能联网，数据流向取决于命令本身，应先确认；不要把密钥放进命令参数。摘要生成失败时保留旧结果并显示失败与过期状态。

也可传入 `--deepseek-model [模型名]`（默认 `deepseek-v4-flash`）改用 DeepSeek：会把所选会话文本（最近最多 8 条、每条截断到 800 字）发送到 `https://api.deepseek.com`，密钥取自 `DEEPSEEK_API_KEY` 或 `~/.claude/secrets/deepseek.key`。实测单条 2–5 秒，一轮最多处理 8 条。摘要出现在卡片预览（有 AI 摘要时替换原话）和抽屉的“摘要”块；失败时卡片退回原话，抽屉显示具体失败原因。

也可传入 `--ollama-model <模型名>` 使用本机 Ollama。qwen3:4b 中文可用但单条要 10–30 秒且吃满 GPU，资源紧张时不建议。

摘要只给“进行中”那一栏的会话（正在运行，或你手动放进进行中），并且跳过后台/子会话和标题以 `btw` 开头的一时之问；不需要给所有会话都做摘要。每轮最多 8 条，且每个会话两次摘要之间至少隔一个刷新间隔；这段时间内没有新消息就不重新生成。输入取最近 12 条消息、每条截断到 1200 字；输出不超过 60 字，只描述 agent 当前状态、结论和卡点，不复述用户说过什么。DeepSeek 开启推理但用最低档（`reasoning_effort: low`，约 150 思考 token），单条约 2–5 秒。卡片显示 3 行、悬停可看全文，抽屉里显示完整摘要。已生成的摘要会保留：会话不再运行时，卡片仍显示上次摘要（变淡表示之后又有新消息）。一次刷新 = 一次同步 + 本轮排队的全部摘要：同步按钮在队列跑完前显示“摘要 d/t”，队列清空后才盖上“同步”时间；没有需要刷新的会话时队列为空，刷新即刻结束。

### 用量

左下角的小胶囊是模型用量：外层显示所选时间范围内的总 token（自动转 K / M / B），悬停展开“自动整理”（摘要）与“我的指令”（看板助手）两部分。范围菜单向上弹出，可选近 1 小时 / 今天（默认，按本地零点算）/ 近 7 天；每个模型调用按时间入库，换范围即时重算。选择记在浏览器本地。

## 看板助手（DeepSeek）

顶部对话图标打开右下角面板，直接用中文下达整理指令，例如“把 7 天没有新消息的会话全部搁置”。助手只通过两个工具行动：

- `list_items`：按栏位、标题、无活动天数、条数预览会话。
- `update_items`：批量改状态 / 标签 / 备注 / 是否隐藏；必须给选择条件，单次最多 300 条；标签用 `list_items` 里看到的名字，替换原有标签、最多 3 个。

它不会删除或修改原生会话，也不碰默认隐藏的后台会话；语义不清或数量过大时会先反问。同一个能力也以 CLI 暴露，方便脚本调用：

```powershell
python D:\CodeSpacegent-workbench\scripts\session_board_cli.py list --lane 进行中
python D:\CodeSpacegent-workbench\scripts\session_board_cli.py set --no-activity-days 7 --state 暂不关注
```

“进行中”栏只包含**运行中，或 30 分钟内有过活动**的会话；“最近”承接超过 30 分钟但在所选时间范围内的会话（栏头可选近 1 天 / 3 天 / 1 周，默认 1 天）；更早的落入“搁置”。时间一律取最后一条真实消息，宿主追加的记账行不算活动。

### 状态与过滤

- **执行状态**（卡片左侧图标，四种颜色）：执行中（绿，转动）、本轮结束（蓝勾，空闲且有未读结果）、空闲（灰点）、状态未知（灰虚线圈）。宿主确认仍活跃但拿不到确切状态时显示“近期活跃”（青色呼吸）。它与管理状态分开展示：管理状态由所在列表达，未读用标题右侧小点表示。“等待输入 / 异常中断”暂未实现——当前没有可靠信号源，宁可不显示也不猜。
- **进行中**：正在运行，或最近 30 分钟内有活动；其余在所选范围（近 1 天 / 3 天 / 1 周）内进入“最近”，更早进入“搁置”。范围在“最近”栏头选择，存在看板库里，前端与助手共用。
- **顶部标签**只有三个：全部、专注、需关注。“专注”不是筛选——它只留“进行中”这一栏并居中显示，用来盯着正在跑的会话；“需关注”是筛选，只留 AI 判定“需要你拍板 / 出现阻塞”的会话（摘要里的 attention 字段），有新结果不代表需要你决策，分组头的“N 需关注”同义。打开抽屉即视为确认：这一版摘要不再标你，卡片上的提示行也收起；之后生成的新摘要若仍要你拍板，标记会重新出现。看板助手用 `attention_only` 过滤这类会话，用 `clear_attention` 清除标记。
- **列折叠**：已完成、搁置默认收进右侧折叠栏（每个一条按钮，显示条数与需关注标记），点一下展开成整列，状态记在浏览器本地。整页滚动，列不再各自滚动。列头与工作区分组头都会显示“N 需关注 / N 新结果”的聚合。
- 卡片预览固定 3 行，悬停浮出全文；完整内容与最近消息在右侧抽屉里。
- **标签**是全局的：名称和颜色存在看板库里，同一个会话最多挂 3 个，也就可以同时出现在多个标签的筛选结果里。顶部标签栏固定保留“全部分组”，标签默认展开 5 个、展开后最多 10 个，其余收进“更多”；末尾的 + 新建标签（名称 + 12 个预设色之一）。标签右侧的 × 删除前会确认，删除只解除所有会话上的关联，不动会话本身；从卡片或抽屉里摘掉标签只影响那一个会话。颜色只用来区分标签身份——深色表面的标签（标签栏、抽屉）用原色 14% 底 + 25% 边框 + 原色字，浅色卡片上用 20% 底、无边框、原色混 55% 深墨的字；不参与运行中 / 需关注 / 新结果这些状态语义。
- 没有任何可展示内容的会话（临时目录里的 worker、刚创建还没消息的会话）不进看板；同一栏里出现同名会话时，标题后会带 4 位 ID 前缀以便区分。
- 内容区最大宽度 1680px 居中，避免超宽屏下每行过长。

## 分层与接入新宿主

```
宿主数据源（transcript / 元数据 / 运行状态 CLI）
      │  session_board_hosts.HostAdapter
      ▼
适配层（解析、分类、运行状态、跳转链接）
      │
      ▼
看板状态（SQLite：items / events / summaries）
      │
      ▼
看板界面 · 助手工具 · CLI
```

宿主相关的逻辑都收在 `scripts/session_board_hosts.py`，核心只调接口、不认识 transcript 格式：

- `transcripts()` 发现会话文件；`classify()` 给出入口、是否人工发起、续接自哪一段；`live()` 给运行状态与 Desktop 链接。
- `hints(record)` 从一行记录里取标题和 cwd；`message(record)` 返回 `(role, text, time)`，不是对话就返回 None；`clean_text(text)` 去掉该宿主的存储包装。
- `is_background(...)` 判断后台/子会话：`injected_prefixes` 列出“看起来像用户消息、其实是 harness 流量”的前缀（系统通知、命令回显、会话间转发的消息），`worker_paths` / `uses_temp` 列出 worker 的工作目录。

这些都是宿主类的属性或方法，扩展时改规则、不改解析代码。看板核心（同步、状态、摘要、助手、CLI）不直接读 `~/.claude` 的任何路径。

接入新宿主（例如 Codex）只需实现一个 `HostAdapter` 子类并在 `HOSTS` 里注册，不用改同步、看板或助手逻辑。当前 `ClaudeDesktopHost` 是唯一实现，`tests/test_session_board.py::test_board_runs_on_any_host_adapter` 用一个假宿主验证了这条缝。

## rewind / 分叉 / 压缩

Claude Code 在 rewind 或 fork 后会写新的 transcript 文件，其中记录里的 `requestSessionId` 指回原会话，Desktop 里仍是同一个会话。适配层解析出这层关系并写入 `items.fork_of`：看板只显示最新那一段，被继续的旧文件不再单独成卡；抽屉顶部提示“含 N 段历史”。若分叉点很早，旧分支独有的内容不会出现在新文件里，只会保留在磁盘上——这一点尚未在 Desktop 侧核实。

上下文压缩同样会换一个 transcript 文件，但新文件先整段重放旧历史，指回旧会话的 `requestSessionId` 落在文件中段，靠读首尾都取不到；因此压缩另走一条更确定的信号：本机 session 元数据里的 `hostSessionId`（Desktop 会话 id）在压缩前后不变，而 `sessionId`（transcript id）会变。同步时用它把新文件链接到旧文件，效果与 rewind 一致。应用内“新建分叉会话”会分配新的 Desktop 会话 id，因此不会被并掉。

### 卡片区域规格

卡片高度由内容决定（不再固定），区域内间距统一 8px；文字超长渐隐，不截半行。

| 区域 | 是否必有 | 尺寸规则 |
| --- | --- | --- |
| 状态图标 | 必有 | 固定 20–22px，与标题首行对齐 |
| 标题 | 必有 | 1–2 行，行高固定；超出省略，抽屉内看全 |
| 未读点 | 可选（有未读时） | 固定 8px |
| 预览 | 有文本时必有 | 1–3 行自适应，超过 3 行底部渐隐；悬停看全文 |
| 关注条 | 可选（AI 判定需拍板/阻塞） | 最多 2 行，出现时才占高度 |
| 页脚 | 必有 | 时间固定右侧；分组标签、后台标签可选；与上方固定 8px 间距 |

等高与零留白无法同时成立：固定高度会在短摘要下产生空白。这里选择内容驱动高度 + 统一间距，实测卡片高度 115–155px。
