# 需求探索

将不完整的材料逐步变成可决策的认识。可以独立调用，也可为 req-align 提供输入；当前任务只要求探索时，交付认识后结束。

## 明确目标与基线

先读项目指令和文档约定，再看用户请求、已有材料及相关当前 Decision/Spec。确定这次要弄清的问题、范围和下一项需要支持的决策；从已知上下文能确定的内容直接采用，只有实质歧义才询问用户。

已有 Decision/Spec 是当前承诺。把新材料中的想法、推荐和已接受选择分开；发现与现行承诺冲突时提出变更问题，不以材料更新或用户未重述旧承诺为由覆盖合同。此时的目标是知道“为什么探索、已有何种依据”，不要求先创建任务包。

## 理解材料

材料多时先看目录、摘要和来源，建立全貌，再深入会改变判断的部分。区分：已确认承诺、可验证事实、约束、候选机制、未知和冲突。对支撑建议的重要事实保留可追溯来源，区分事实与推断；记录无法读取或尚未核实的关键材料，不能把未读当成不存在。

优先使用拥有该事实的当前来源。来源矛盾时查明时间、适用条件和权威范围，不能仅凭最新或最多人提及便选定答案。分类服务理解，不要求逐文件产出分类表。

## 按问题推进

选择能改变方向、可行性或重要边界的下一问题。依赖前置答案的问题暂缓，独立问题可继续；根据新证据重看候选与范围，不预先穷举实施步骤。

| 当前需要 | 采用的方法 |
| --- | --- |
| 查清有边界的事实 | 读取 [research](../research/SKILL.md)，按一手来源调查并综合结果 |
| 在有实际差异的方向间取舍 | 读取 [grilling](../grilling/SKILL.md)，把本次探索目标作为质询范围，给出依据与推荐，等待用户选择 |
| 通过具体行为或形状帮助判断 | 在已有授权范围内读取 [prototype](../prototype/SKILL.md)，用可回收原型回答指定问题 |
| 工作适合委派或并行 | 读取 [Dispatcher](../dispatcher/SKILL.md)，由其处理委派、资源与返回；规模小的调查直接完成 |

已能准确表述的问题即使被阻塞，也应保留其问题与依赖。尚无法准确表述的区域只记录当前疑点，等前置答案出现再展开。已排除的未来范围不作为未完成工作反复引入；局部算法和实现组织不必提前决定。

普通任务范围内的只读调查可直接进行。原型代码、环境变更、付费操作和外部写入按已有授权判断；缺授权时只暂停相关动作，继续不依赖它的工作。原型反馈用于决策，不能证明真实集成或生产能力已经成立。

## 综合与停止

每次得到重要答案，更新当前认识：它支持或否定了什么，是否解锁新问题，是否改变推荐。需要人的取舍交给人；可以通过调查获得的事实由 Agent 查清。

当可靠事实足以支持当前目标、现实方向能够比较、重要未知及其影响均已明确时，给出决策依据。仍有会改变可行性或安全边界的事实缺口时，说明当前能判断到哪里、缺什么、怎样继续；不能用未经验证的假设宣称路线已清楚。待用户选择可以作为本轮交接，不冒充已接受的方向。

交付包括本次目标、可靠依据、适用的方向选项与推荐理由、关键未决项和最小下一步。没有真实多选时直接说明结论，不制造备选。用户仅要求探索时停在这里；来自 req-align 的调用返回该入口，由它继续判断是否具备正式起草条件。

探索不写正式 Decision/Spec、不设置 Gate 或实施状态。已经进入正式阶段的调用仍遵守调用方既有 Gate 和授权；探索结果只补充依据，不解除其阻塞或替代正式验收。

## 留档与续接

短探索直接在会话中交付。用户要求保存、明确在 investigations 中持续探索，或需要跨会话恢复时，依项目文档约定维护一份主题探索摘要。先找已有位置与同主题摘要；有多个合理目的地时只澄清位置，没有约定时在实际需要留档时与用户确定路径。

保留原始材料，以链接引用；摘要呈现目标、事实与来源、候选与理由、未知或冲突、下一步。尚未看清及明确排除的范围仅在有恢复价值时记录。沿用同一份摘要，不增加认领、状态机、采用记录或计数要求。

续接先读摘要，再检查影响当前问题的来源变化；被新证据推翻的认识要明确修正。摘要是探索参考，后续 Decision/Spec 必须自足表达已接受的方向与合同，不能将必须遵守的规则藏在 investigations 中。
