## 原则

- [待验证] 候选处理应区分“直接改写”“保留专业 token 并说明”“需要决定”，避免机械翻译或以语言改写暗改合同。（证据: R1）
- [待验证] 文档对象包括英文短语、中文直译词、中英混搭、标题和文件名；确认重命名时必须同步检查链接与旧路径。（证据: R1）
- [待验证] 默认批次继续保持最多 20 个，不收紧为 8–12 个。（证据: R1）
- [待验证] 使用一个共享 Core，并按处理对象只分为会话类和文档类；first shot、重述、检查和回写不各自建立模式。（证据: R2）
- [待验证] 文档类把用户确认作为分析与 apply 之间的主路径检查点，不为确认另建批准模式。（证据: R2）
- [待验证] 词汇实例是 Core 的首次加载材料，当前上下文已加载时直接复用；会话类不加载文档扫描、确认、apply 和验证指导，文档修改流程只从文档 Router 进入。（证据: R3）
