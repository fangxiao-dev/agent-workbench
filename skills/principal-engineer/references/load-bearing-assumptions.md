# 承重假设

**承重假设**是以陈述句出现、从未被论证过的选择：换掉它，已完成和计划中的工作要**全部重做**。

扫描只就着 Owner 提供的材料做，不顺着记忆或仓库去找补充材料；缺什么在最后说明。

## 校准：什么算、什么不算

开始扫描前先读完本节。不带校准时，技术选型和执行偏好会被误判成承重假设，而 B 类会被整个漏掉。

- 「用 Postgres 而不是 MySQL」——若已被论证过，它是已作出的选择。只翻**从未被表述为选择**的东西。
- 「按钮放左边」——换掉只需局部调整，影响面不够。
- 「先写测试再写实现」——除非它决定了整个承载结构，否则属于执行偏好。

判据只有一条：**换掉它，是不是全部重做。**

## 1. 抓承重假设

**A · 事情被描述的方式。** 找以陈述句出现、通篇没被论证过的组织性选择：「按 X 做 Y」里的 X，或一份文档从标题起就当作既定事实的东西。只找这类表述，不顺着材料的逻辑往下读——写成文字之后假设已被固化，顺着读只会读到它的自洽性。

**B · 已写下的约束的合取。** 每条约束单看都对，加起来却把某个量锁死。把散落的「唯一 / 独占 / 单写 / 必须经过 / forward-only / 串行 / 共享同一个」条款拉到一起，问：

> **这组约束加起来，把什么锁成了 1？**

再问实际要的是几。两个数对不上，就是一个已经生效的承重假设。

对每个候选问：如果它是错的，什么会全部重做？答得出才保留。通常 1–3 个；五个以上说明判据用松了，那是 `grilling` 的粒度，回到校准重筛。

## 2. 摆替代方案

每个承重假设配 3–4 个**根本不同**的替代方案，任一条不满足就重新生成，不在原方案上打补丁：

- 所有候选不能被同一句话概括，否则只是变体；
- 至少一个直接违反原假设；
- 每个候选写出「它成立的前提」。

每个候选具体到能在脑中放一遍：第一波做什么、第一次汇合/验证在什么时候、完成后长什么样。

## 3. 先中立呈现，再判断

一个承重假设一张表：`候选 / 成立前提 / 第一波 / 第一次汇合 / 完成后`。全部一次给出，**不推荐、不排序、不暗示倾向**——推荐一旦先出，Owner 一眼看出哪个契合的能力就被锚定了。

Owner 表态或要求意见后，再给出倾向和理由，回到主流程的「给出当前决策」。

## 案例：各自正确的约束，但漏了关键路径

**任务表述：** 「帮我把这个 Lark → Supabase 迁移按纵切一条条切好。」

**写在表述里的：`按纵切`。** 任务包文档从标题起就把它当既定事实，全文没有论证为什么按业务域切。

**谁都没说过的：单通道不会成为关键路径。** 由三处各自正确的条款合取而成：

| 出处 | 原话 | 单看对不对 |
| --- | --- | --- |
| 决策 | Test 资源由迁移环境**独占**，理由是**保持单写 authority** | 对，环境隔离必需 |
| 规格 | 最终编号与共享 Test apply 由**父包单写管理**；证据链 **forward-only** | 对，防分叉防假绿 |
| 计划 | 四条纵切并行 | 对，分工合理 |

前两行拉到一起问「锁成了 1？」——同时能推进 schema 的线数 = **1**；计划要 **4**。换掉它，四个任务包、三百多个提交的组织结构全部作废 → 承重。

| 候选 | 成立前提 | 第一波 | 第一次汇合 | 完成后 |
| --- | --- | --- | --- | --- |
| A 中央父包单写基础，四包交付纵切 | **中央通道能及时供给 seam，串行 promotion 成本可控** | 四线各自开 draft | 父包统一集成 | 单一 canonical history |
| B 基础升格为同级包，另设轻量发布包 | 基础、业务迁移、发布的生命周期彼此独立 | 抽离基础与切换所有权 | 基础 gate 被四包共同消费 | 各自拥有清晰终点 |
| C 各业务包拥有本域 schema 与 migration，中央只管兼容与版本清单 | 领域边界稳定，跨域兼容可自动验证 | 明确每域 migration 归属 | 用兼容合同汇合，不进共享单队列 | 各域独立可验证 |
| D 取消固定域拆分，改按风险波次组织 | 读路径、事务写路径、外部副作用的验证差异大于领域差异 | 把工作映射到三类风险波 | 第一波完成后再启动下一波 | 每波自带组合证据 |

Owner 读到 A 的成立前提那一格，会认出它正是后来被违反的那一条。实际结果：假设未被检验，四线并行六周，大部分产出从未汇合，阻塞多是在等流程而不是等技术能力。

**要点：** B 类假设没有出处可引，只能靠把「唯一 / 独占 / 单写 / forward-only」这类词全部拉到一起才逼得出来。它最容易漏，也最值钱。
