# 普通任务交接

适用于一般讨论、调查、制作与执行任务，也包括只有调研／规划材料、尚未初始化运行状态的包。

## 围绕下一项判断组织内容

用一两句话交清这件事为什么存在、接手者要取得什么结果。按需要补充前因后果、关键决定、当前成果、未解决问题、目标和推荐下一步；已有来源足以说明的内容直接引用，不要求固定章节齐全。

给最短有序阅读路径，每个入口说明“回答什么问题、为什么此时读”。顺序由理解依赖决定：需要先理解问题就先给问题来源；已有明确成果可直接从成果继续。阅读顺序不提升来源权威，研究意见、已采用决定与实时状态应能分辨。

明确阅读后的首个判断和产出。未知且必要的输入列为开放问题，不从聊天推测补成已定事实。推荐动作不自动产生执行或外部副作用授权。

## 按需携带现场状态

有工作树的执行任务仅补影响下一动作的工作目录、改动归属、并行操作和授权；一般知识讨论不要求Git快照。没有checkpoint或package state不妨碍交接，不为了交接创建它们。提交、知识沉淀和环境整理由用户当次要求或原任务流程决定。

用户约束、未沉淀经验与交付格式统一使用主干要求。
