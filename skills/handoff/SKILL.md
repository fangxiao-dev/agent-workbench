# 交接

把当前会话压缩成一份下一位 agent 能在没有聊天历史时独立判断并行动的冷启动地图。Handoff 不按文档权威等级机械排序，也不复述时间线；它按接手者完成下一项判断所需的**认知依赖**组织入口、已定事项、开放问题和行动边界。

## 输出位置

把 handoff 文档保存到用户 OS 的临时目录，不要保存在当前 workspace。完成后把文件路径告诉用户。

## 主流程

### 1. 锁定接手任务

把用户参数或补充说明作为下一 session 的 focus。先用两句话写清：

- **首个判断**：接手者理解材料后首先必须判断、决定或恢复什么；
- **首个产出**：完成该判断后应给出什么结果或执行什么动作。

围绕这两句话收窄范围。排除不会改变首个判断或首个产出的历史、旁支、已关闭问题和旧日志。

完成标准：即使删除全部聊天历史，仍能说出“接手者先判断 X，然后产出/执行 Y”。

### 2. 建立认知依赖

列出首个判断依赖的事实，并为每项事实找到现有来源。来源可能承担不同角色：原始问题或证据、采用后的研究结论、Decision/Spec/ADR、计划与 checkpoint、Git/live state、外部 artifact。角色用于解释来源，不预设阅读顺序。没有可靠来源的必要事实进入“开放 / 缺失输入”，不从聊天记忆补成既定结论。

按依赖关系排序：如果来源 B 使用了只有来源 A 才解释的概念、问题或结论，则 A 在 B 之前。问题来源通常先于解决该问题的 Decision；恢复已登记执行时，current checkpoint 可以先于其历史理由。顺序由接手任务决定，不由“Ideas、Spec、Plan、最新文件”之类固定层级决定。

阅读顺序与 authority 正交：来源靠前只表示它是理解后续材料的前提，不提升其裁决权。Handoff 同时标明“为什么先读”和“谁拥有最终事实或行为合同”，避免把 research/Ideas 误当成 Spec，也避免让 Spec 取代问题来源。

每个入口都写成：

```text
<path / URL> — 为了回答什么 — 为什么此时读取
```

只保留形成最短完整依赖链的入口。后续才可能需要的材料明确标为按需读取，不放进启动路径。

完成标准：启动路径中的每个后续来源都能用前序来源理解；没有未定义概念、隐含聊天结论或需要接手者猜测的阅读顺序。

### 3. 分离事实层

把 handoff 中的结论分成四类，避免阶段和 authority 混写：

- **已定**：已有来源支持、下一 session 不应重新裁决的事项；
- **开放**：仍需调查、讨论、验证或 owner 决定的事项；
- **当前态**：会改变下一动作的 branch、HEAD、dirty state、attempt、Gate、阻塞或并行操作；
- **边界**：授权、安全、外部副作用和明确停止条件。

只在当前态会改变下一动作或保护现有工作时记录它；普通知识讨论不因为仓库存在就自动携带完整 Git 快照。实现完成、验证通过、Ticket 验收、package closed、合入和发布分别陈述，不互相代替。

完成标准：每个重要主张都能判断属于哪一类，并能回到来源；开放问题没有被写成既定事实。

### 4. 组装冷启动地图

按接手者的认知过程写，而不是套用某一业务场景：

```markdown
# 交接：<简短名称>

日期：<YYYY-MM-DD>

## 这是什么 / 为什么现在接手

## 冷启动阅读路径

## 阅读后的首个判断与产出

## 已定

## 开放

## 当前态与边界（仅在会改变动作时保留）
```

标题可以按任务删减或增加，但必须保留“orientation → ordered route → first judgment/output”这条主线。Handoff 只给接手所需的最小控制图，不建立第二份 PRD、Spec、Plan、Gate 或研究报告。

如果下一 session 要继续代码、测试、implementation package 或其他有工作树状态的执行任务，读取 [`references/task-execution.md`](references/task-execution.md)。它只补充执行恢复所需的 compact anchor、live snapshot 和授权字段；认知依赖仍由本文件决定。

### 5. 做冷启动验收

把接手者视为不知道当前聊天的人，只允许其读取 handoff 指定的入口。逐项确认他能回答：

1. 这件事为什么存在，当前要取得什么结果？
2. 哪些是来源事实、哪些是已经采用的决定、哪些只是 live state？
3. 已经解决或完成了什么，仍然缺什么？
4. 下一 session 首先要判断什么，输出或执行什么？
5. 哪些动作越权、危险或需要停下来请求输入？

如果任一答案依赖聊天记忆，修复认知依赖或入口说明；不要用一段更长的历史摘要掩盖缺口。

完成标准：五个答案都能从 handoff 与入口机械回溯，且接手者无需发明首个动作。

## 引用优先

不要复制已经存在于 PRD、plan、ADR、issue、commit、diff、测试日志或 artifact 里的内容。引用必须同时承担定位和认知路由：

- artifact 路径或 URL；
- 它回答的问题；
- 它在依赖链中的位置或按需触发条件。

同一目录下的多个权威文件，用“base directory + filenames”表达，不要逐条写绝对路径。只有跨仓库、临时目录、外部 artifact、下载文件或其他容易找错的位置，才使用绝对路径。

避免包含：

- 已在 plan.md 中列出的完整文件清单。
- 已在 gate.md 中列出的完整测试矩阵。
- 长 diff、长日志、完整 API payload、完整业务数据。
- 可从 commit 或 issue 直接读取的细节。

## 安全与脱敏

Redact API keys、passwords、tokens、PII 和其他敏感信息。不要粘贴完整外部 API payload、完整客户/订单/商品敏感数据或可复现凭证；给摘要和 evidence 路径即可。

## 启动入口

启动入口可以是一个文件，也可以是一条最短有序依赖链；数量由首个判断的认知依赖决定，不强求单文件。不要枚举后续可能使用的 skills，也不要把延后 skill 名称写入待粘贴的新 session prompt，因为显式名称可能触发立即读取并挤占启动上下文。后续 skill 由实际执行 seam 按需触发。
