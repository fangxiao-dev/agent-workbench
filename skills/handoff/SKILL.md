# 交接

只补接手者无法从现有材料或 harness 恢复的信息。交接是接手任务的入口，不是第二份计划或状态记录。

## 1. 确定接手目标与路由

明确接手者接下来要取得什么结果，再按当前工作的管理方式读取一份参考：

- 当前工作处于 Impl-Package 开发中、由其 harness 管理：读取 [Impl-Package 交接](references/impl-package.md)。
- 普通任务，或只有调研／规划材料、尚未初始化运行状态：读取 [普通任务交接](references/ordinary-task.md)。

仓库里存在 package 不代表当前任务属于第一种模式。仅在缺少的信息会改变接手目标时询问用户。

## 2. 补齐必要信息

按所选参考组织最短恢复路径。主控判断现有文档或 harness 足以恢复的背景、决定、成果、开放问题和下一步，可以省略。

两种模式都补充入口未覆盖的用户行为要求、已有授权、禁止事项、并行工作和现场约束；区分用户明确要求与建议，不把上一会话的临时选择提升为长期规则。

### 本 session 尚未沉淀的经验

交接内容固定保留同名章节，没有内容写“无”。按 [learn-lessons](../learn-lessons/SKILL.md) 的耐久性门槛筛选：非显然、值得复用、有代码／测试或实际运行证据，且尚未进入长青文档。

每条简述症状或容易误判之处、已验证的做法或失败尝试、证据入口及适用边界。未证实推测放入开放问题；已有长青覆盖直接引用；一次性日志与无关历史不带入。这里是待沉淀线索，不执行知识回刷，也不将其作为交接前置条件。

## 3. 输出与检查

默认输出可复制的交接文本；用户需要文件时才保存到 OS 临时目录，并给出路径。

已有 artifact 采用引用，说明它回答什么、何时读取。同目录材料使用 base directory + filenames；跨仓库或容易找错的工作目录用绝对路径。移除凭据、个人信息、完整业务数据及原始payload。

完成前以不了解聊天历史的接手者检查：能否定位恢复入口与接手目标、区分已定与开放事项、找到必要约束和经验，并知道恢复后首先判断或执行什么。缺口通过补入口或必要事实解决，不用长篇时间线掩盖。
