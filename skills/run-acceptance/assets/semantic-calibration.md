# 业务语义校准样例（通用）

这份清单给业务复审者校准“不合逻辑”的尺度：每类问题配一个反例和判断要点。项目自己的样例放在项目 QA skill 里。

每次复审发现新的问题类型，由主控补进本表。

| 类型 | 反例 | 判断要点 |
|---|---|---|
| 视角错位 | 员工的待办写着“还有人没报班”（这是管理者的说法）；员工看自己的待办，标题前挂着本人姓名 | 同一条数据在不同角色的页面上，需要各自的措辞；先看文案里的动作主体是不是当前角色能做或该看到的事 |
| 永远为空的字段 | 组织级事项的“门店”栏恒为“—”；“本月资料 —” | 字段对这类对象不适用时就不显示，不要拿“—”占位 |
| 开发备忘外露 | 页面写着“服务端暂时没提供，所以这页没有……”，或用“服务端”这类词解释数字来源 | 用户界面只写业务含义和用户能做的事 |
| 状态与动作矛盾 | 页面写“这个月还没有录入工资单”，旁边却给“去重录工资单”链接 | 链接、按钮必须和当前状态一致 |
| 反馈不具体 | 操作成功后横幅只写“已完成。”，而且一直不消失 | 写明完成了什么，可以关闭，或者自动消失 |
| 标题与内容不符 | 应用副标题只提“入职”，页面却已有工时、工资 | 概括性的文字要随功能范围更新 |
| 合计口径不清 | “4 人 · 税前 €423”实际只算了 3 人，手填奖金也不在内 | 写明算了谁、没算谁、为什么没算 |
| 缺少核对依据 | 核对页只有金额，没有工时和时薪 | 核对页要给出能自行验算的数 |
| 后果不说明 | 放行、作废、取消按钮旁没说对他人有什么影响 | 不可撤销或对他人可见的动作，要在按钮旁说明后果 |
| 危险动作不醒目 | “取消登记”和“上传票据”外观一样，点击即生效 | 不可恢复的动作要先确认，并用危险样式 |
| 默认落在空状态 | 列表默认显示本月，结果为空，上个月的数据却被漏看 | 默认值为空时，要提示别处有数据 |
| 要用户提供系统数据 | 让员工手填城市经纬度 | 用户不该知道的数据，由系统获取 |
| 文字框控件 | 带边框或下划线的文字块，看起来半像链接、半像按钮 | 要么是普通文字，要么是正式按钮（主按钮或设计系统的次级按钮） |
| 术语与语言混杂 | 同一屏里出现“工资单 / 我的工资单 / 薪资”三种叫法；中文页面里夹着德文词 | 同一对象一个叫法，界面跟随语言 |
| 自相矛盾的承诺 | 说明写“封账时交给税务师”，但封账后新增的不在其中 | 说明文字要和实际结果一致 |
| 内部代码外露 | 用户可见的错误提示里出现 `E_1234` 这类错误码、请求号、数据库 ID 或裸编号，旁边没有用户能执行的话 | 用户只看得懂业务语言；错误码进日志，页面写原因和下一步 |
| 无权入口未隐藏 | 没有某权限的角色仍看到对应菜单、按钮或页签，点进去才提示无权 | 入口可见就表示可用；没权限就不显示，或明确置灰并说明缺什么权限 |
| 说明小字常驻 | 同一句业务规则说明在标题下、控件旁、表格底各出现一次，长期挂在界面上 | 规则说明放一次，只在用户要做这个决定的地方出现 |
| 窄屏长词挤压 | 视口压到项目支持的最窄宽度时，未缩写的长术语把表头折成两三行、挤掉列宽或截断顶栏 | 在项目声明的最窄宽度下检查长术语；按惯例缩写、允许换行或给容器留空间 |
| 数据或时钟造成的假象 | 同一现象只在单个夹具出现、同一批截图出现两个“今天”、后台任务没启动时列表为空；换真实数据或时钟后消失 | 先排除夹具、测试时钟和未启动的后台任务；排除后再报，拿不准的放“待确认” |
