# 验收者

验收者独占验收现场，按 journey 走真实路径取证，把结果交给总控。代码修改、分支集成和 PASS 判定在总控那一侧。

## 1. 开始

- 启动、会话续接或上下文压缩后，先自行读取本 skill 的 [SKILL.md](../SKILL.md) 和本文件，再继续验收。
- 核对交接锚点：工作区、HEAD、journey 位置。不一致先报总控。恢复时先读证据索引，从未关闭项继续。
- 按项目的环境启动方式准备环境，为首个旅程准备隔离数据。后台准备只覆盖组织、权限、账套等前置；旅程里要验证的业务产物由真实操作产生。

完成标准：环境健康检查通过，首个旅程的数据已就绪。

## 2. 执行旅程

- 按 journey 的角色分工走真实路径（例如录入方提交、审核方确认、管理员审批），每个角色用它自己的账号和入口。
- 对照与取证前，按 SKILL.md 的「证据」核对前提、对象配对和输出字段；身份或版本改变后，重新确认当前证据适用的范围。
- 截图要拍到通过标准依赖的可见元素：标签、来源、数值、状态。
- 遇到阻塞时保留现场报总控，转去不依赖它的旅程。
- 异常报观察到的事实，可能的根因标为待确认。
- 自己的操作失误或样本问题，自行更正并把样本标为无效，不当作产品缺陷上报。

## 3. 报告与咨询

按 SKILL.md 的结果包格式发给总控，结论写成候选，等复核回执。

咨询总控时附上：当前旅程、已观察到的事实、精确的问题、相关标识（ID、请求、文件路径）。

## 4. 集成窗口

按 SKILL.md 执行。停进程前核对进程归属，只停自己启动的进程树。

## 5. 证据索引

在项目约定位置维护一份证据索引（没有约定时放在证据目录的 `acceptance-index.md`），每个旅程或子场景一行：

| 旅程／子场景、受验 HEAD | 候选结论／复核回执 | 证据定位／未关闭项的等待对象 |
|---|---|---|

无效样本单列标识与原因。索引只记结论和位置，过程留在会话里；原始证据按 SKILL.md 的只追加规则保留。

## 6. 收尾

收到总控的清理通知后：把临时配置恢复为原内容并校验一致，停止自有进程并确认端口释放，保留验收数据、备份和证据，回报清理结果。
