# 验收者

验收者独占验收现场，按 journey 走真实路径取证，把结果交给主控。可以是独立 session 或主控派出的子代理。代码修改、分支集成和 PASS 判定在主控那一侧。

## 1. 开始

- 启动、会话续接或上下文压缩后，先自行读取本 skill 的 [SKILL.md](../SKILL.md) 和本文件，再继续验收。
- 核对交接锚点：工作区、HEAD、journey 位置。不一致先报主控。恢复时先读证据索引，从未关闭项继续。
- 按项目的环境启动方式准备环境，为首个旅程准备隔离数据。后台准备只覆盖组织、权限、账套等前置；旅程里要验证的业务产物由真实操作产生。先复用项目已有的种子或场景脚本，再考虑新写。
- 某个前置状态要靠其他角色的长链路才能造出（例如另一端的正式确认），且不是本旅程要验证的对象时，不硬磨：报主控，附已尝试的路径与证据。主控可批准用等效状态的样本替代，前提是该状态到页面结果的规则已有单测覆盖；替代作为偏差写进走查记录。

完成标准：环境健康检查通过，首个旅程的数据已就绪。

## 2. 走查旅程

按 journey 的角色分工走真实路径（例如录入方提交、审核方确认、管理员审批），每个角色用它自己的账号和入口。

**页面步**

- 用你自带的内置浏览器工具走查（Claude 用自己的浏览器工具，Codex 用 codex in chrome，其余按宿主），每步操作后截图，截图拍到通过标准依赖的可见元素：标签、来源、数值、状态。默认尺寸拍不全或布局被挤成窄屏形态时，先试着调整视口或窗口尺寸再截图；用什么方法、设多大，按你的宿主工具能做到的自行选择。Claude 子代理用 Claude in Chrome 时，先以 `createIfEmpty: true` 建自己的标签组，结束时关掉自己的标签。
- 每步按[走查记录模板](../assets/walkthrough-record.md)落一行，截图存 package 的 `evidence/` 目录。走查人写你自己的标识，登记时作为 `manualBy`。
- Journey 的“取证：”行写了 Playwright 的步骤，那一步改跑 Playwright 脚本并保存 trace；其余步仍走查。
- 命中模板“须 Owner 本人验”的步骤，备好入口与读回方法，标“待 Owner”。

**文件步与记录步**：登记用户实际收到的文件，或 package 内的日志文件；格式见 current-state 的 evidence 表。

**节奏与提交**

- 每走通一条旅程（走查记录与截图齐全），提交一次。
- 一个 run 中途修过数据或代码，该 run 不再算连续：先前的走查只作预演，收口前在最终 HEAD 上用新 run 从第 1 步连续重走。
- 对照与取证前，按 SKILL.md 的「证据」核对前提、对象配对和输出字段；身份或版本改变后，重新确认当前证据适用的范围。
- 遇到阻塞时保留现场报主控，转去不依赖它的旅程。

**失败**

- 失败先看证据：截图、DOM、console、API 返回，再改。从证据推出原因后动手，不对着代码盲试。
- 自己的操作失误或样本问题，自行更正并把样本标为无效，不当作产品缺陷上报。
- 同一类失败连续两次，停下并问主控：错误原文、截图路径、你的判断、建议选项（各选项的代价）。异常报观察到的事实，可能的根因标为待确认。
- 观察到的产品行为与 Journey 的前提不符（例如 Journey 假设的操作入口在该角色或模式下根本不存在），立即报主控，附基线行为的证据；不改预期、不绕路。

## 3. 报告与咨询

按 SKILL.md 的结果包格式发给主控，结论写成候选，等主控核对截图后的判定。

咨询主控时附上：当前旅程、已观察到的事实、精确的问题、相关标识（ID、请求、文件路径）。

## 4. 集成窗口

按 SKILL.md 执行。停进程前核对进程归属，只停自己启动的进程树。

## 5. 证据索引

在项目约定位置维护一份证据索引（没有约定时放在证据目录的 `acceptance-index.md`），每个旅程或子场景一行：

| 旅程／子场景、受验 HEAD | 候选结论／复核回执 | 证据定位／未关闭项的等待对象 |
|---|---|---|

证据定位指向该旅程的走查记录。无效样本单列标识与原因。索引只记结论和位置，过程留在走查记录里；原始证据按 SKILL.md 的只追加规则保留。

## 6. 收尾

收到主控的清理通知后：把临时配置恢复为原内容并校验一致，停止自有进程并确认端口释放，保留验收数据、备份和证据，回报清理结果。
