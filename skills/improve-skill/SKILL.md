# improve-skill

维护 skill 优化偏好的闭环：先读偏好再提建议，观察用户取舍，确认后把偏好沉淀回 rubric。这个 skill 是维护期辅助工具，不是执行优化修改的 skill。

## 适用场景

使用本 skill 当用户：

- 要求“看看这个 skill 有什么可优化的点”。
- 在多个优化项之间选择、舍弃、排序或要求解释取舍。
- 说“记住我对这个 skill 的偏好”“以后别再提这类优化”。
- 要求分析自己为什么接受或拒绝某个 skill 优化建议。

不要用本 skill 来：

- 直接执行目标 skill 的内容修改。
- 从普通会话自动孵化新 skill。
- 建立用户全局人格画像。
- 把 rubric 内容写进目标 `SKILL.md` 正文。

## Rubric 位置

所有 rubric 路径都以 `agent-workbench` 仓库根为基准，不以当前项目 cwd 为基准。先定位包含 `skills/improve-skill/SKILL.md` 的 workbench 根；如果无法可靠定位，先向用户确认 workbench 根路径，不要把 rubric 写散到目标项目。

优先把偏好写在被维护 skill 旁边：

```text
skills/<target-skill>/rubric.md
```

如果目标不在当前仓库内，例如来自 plugin cache 或外部路径，使用：

```text
docs/rubrics/<slug>.md
```

该 fallback 也位于 workbench 根下。外部 fallback rubric 的 frontmatter 必须包含 `target_path`，记录真实目标路径。

全局偏好层固定为：

```text
skills/improve-skill/global-rubric.md
```

当 per-skill rubric 不存在时，用 `assets/templates/rubric.md` 创建。

## Rubric 结构

rubric 用中文书写，包含原则区和滚动证据区：

```markdown
---
target: skills/dev-with-track
updated: 2026-07-08
---
## 原则
- [已确认] 不接受为边缘 case 增加流程步骤的优化
- [待验证] 偏好删减章节而非新增（证据: R3, R5）

## 决策记录（滚动，最近 ≤5 轮）
### R3 · 2026-07-08
- 采纳「合并 gate 模板重复段」— 用户原话：维护两份必然漂移
- 否决「增加回滚演练小节」— 推断：收益只覆盖罕见场景
```

`global-rubric.md` 使用同构结构，frontmatter 的 `target` 固定为 `global`。

一轮指一条决策记录 `Rn`，不是一次聊天，也不是单个候选项。一个决策记录可以同时包含多个采纳和否决，但作为一次后续印证计数。

## 提案阶段

当用户要求优化建议：

1. 定位目标 skill，并读取 `global-rubric.md` 与目标 rubric。
2. 先用代码库事实和目标 `SKILL.md` 生成候选优化项。
3. 与 `[已确认]` 原则冲突的候选直接过滤。
4. 过滤时用一句话报备被过滤类别，避免错误原则让某类建议永久不可见。
5. `[待验证]` 原则只影响排序和标注，不用于过滤。
6. 呈现候选时说明其与偏好的关系，例如“符合你已确认的少流程偏好”或“试探你上轮提到的删减倾向”。

如果没有 rubric，先按模板创建空 rubric，再按无历史偏好的方式提案。

## 记录阶段

当用户采纳、否决或排序优化项后：

1. 分析取舍背后的偏好，区分用户原话、事实理由和模型推断。
2. 写入前必须口头确认推断，例如：“我理解你否决 X 是因为它为低频场景增加流程步骤。记为待验证原则，对吗？”
3. 如果用户纠正，以用户纠正后的理由为准。
4. 判断写入目标：默认写 skill 级 rubric。
5. 只有同一偏好在第二个不同 skill 上再次得到用户确认，才提升到 `global-rubric.md`。
6. 写入或整理 rubric 时同步更新 frontmatter 的 `updated:` 日期。
7. 写入后静默执行回收、升级和证据裁剪。

只有“推断出的偏好”需要写前确认。机械清理、证据裁剪、日期更新和状态升级不需要额外确认。

## 回收与升级规则

- 新原则默认写为 `[待验证]`。
- 待验证原则用 `（证据: R3, R5）` 累积支持它的决策记录引用。
- 待验证原则在创建后又被 2 条不同的后续决策记录支持时，升级为 `[已确认]`。
- 原则升级后删除名下证据引用；原则已经成为结论，不再保留试用期材料。
- `[已确认]` 原则被用户明确纠正或反驳时，立即改写或降级为 `[待验证]`，并追加反驳证据记录。
- 如果只是模型观察到用户选择似乎和 `[已确认]` 原则冲突，先暂停用该原则硬过滤，并向用户确认是否要修正原则。
- 决策记录只保留最近 5 轮。
- 未转正且证据过期的原则应连同证据一起清退。
- skill 级原则与全局原则冲突时，skill 级优先。
- 不把同一偏好同时重复写进 skill 级和全局层；全局层只保存跨 skill 稳定偏好。

## 输出纪律

在回复用户时保持三个边界：

- 提案时说清哪些建议被偏好过滤或降权。
- 记录时先确认偏好，再写文件。
- 完成后只汇报 rubric 变化，不声称已经优化了目标 skill。

如果用户随后要求执行选中的优化，交还给当前会话或更合适的 skill，例如 `skill-creator`；本 skill 不继续占用执行职责。
