# 积木与公共约定

业务方材料（探索 / 拍板 / 汇报）都由「范式 + 积木」组成。范式定骨架，积木按需取用；积木的现成写法都在 `deck.html` 里，复制那一段即可。

## 每份 HTML 都必须有

- **意见入口**：每页（或每题）一个，按稳定 id 存，不按页码、不按标题存。
- **本机自动保存**：`localStorage`，键名 `CONFIG.storeKey` 每份材料唯一。
- **全局导出**：一个按钮导出全部意见和选择为 Markdown，按页或按题排列，每条带 id；空白不导出。
- **清空重来**：带确认框，提示先导出。
- **用途标注**：`CONFIG.intent` 写明探索 / 拍板 / 汇报，下一个接手改版的 session 据此判断按哪套规则改。
- 无外部依赖，浏览器直接打开；交付时告诉对方「只存在这台电脑的这个浏览器里，换设备前先导出」。

## 可选积木

| 积木 | 用在 | 写法要点 |
|---|---|---|
| 总览页 | 汇报必有；探索可写「这次想弄清什么 / 已确认 / 需要你选」 | 放第一页，不另设开场页 |
| 左侧目录 | 讲解超过 5 页 | 写过意见的页标 ● |
| 界面示意 `.mock` | 对方要判断「看到什么」 | 文案用产品里的真实原文；示意图要说明不是截图 |
| 情况切换 `data-case` | 同一画面有几种情况 | 一组只显示一种，第一个为默认 |
| 确认项 `.confirm` | 讲解中夹着要拍板的点 | 见下方「题号」；涉及法规、税务、法律加 `data-law` |
| 上次已确认 `.settled` | 多轮探索的第二轮起 | 只读展示，不再让对方选，不进导出 |
| 场景表、流程条、对比卡片 | 按内容选 | 业务语言，不出现字段、接口、状态 |

## 题号与改版

- 题号（确认项、问卷题）稳定、映射到来源条目、永不复用；删题不把号给新题。
- 发出前留一份「题号 → 来源条目」对照（来源文档里或旁边的 `.mapping.md`），回填按它走。
- 改版沿用旧号和旧 `storeKey`；合并题记 `from: [旧题号]`。
- 题号整体重编（例如第二轮把 C 系列改成 D 系列）时换 `storeKey`，并先请对方导出上一轮意见，避免旧答复对错题。

## 推荐与选项

- 推荐必须是你愿意直接落地的默认，写具体值（谁、几天、哪种）。
- 讲解里的确认项只给「同意 / 不同意 + 说明」；问卷范式另有「未来再做 / 不做 / 我的意见」。再点一次已选项即取消。
- 未答、含糊、冲突的一律保持待确认，不按推荐处理。

## 维护

发现更好的写法：改 `deck.html` 或 `questionnaire.html`，在 `README.md` 的「来源」里记一行（哪次对齐、改了什么）。同一段代码在三份以上材料里原样出现，再考虑抽成独立组件。
